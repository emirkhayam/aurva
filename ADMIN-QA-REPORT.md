## Баги

### 🔴 BUG-1 (CRITICAL): Редактирование участника крашит страницу
Клик «Редактировать» у любого участника → `TypeError: Cannot read properties of undefined (reading 'split')`. Форма не открывается.
- **Причина:** API `/api/members` отдаёт **snake_case** (`is_active`, `display_order`, `joined_date`, `created_at`), а `admin-panel/src/pages/Members.tsx` читает **camelCase** (`member.isActive`, `member.displayOrder`, `member.joinedDate`). Строка `member.joinedDate.split('T')[0]` падает на `undefined`.
- **Следствия того же несовпадения (видно без клика):**
  - статус всегда «Неактивный» (в БД `is_active=true` у всех);
  - «Порядок:» пустой;
  - «Вступил: Invalid Date».
- **Фикс:** привести `Members.tsx` к snake_case полям + null-guard на `joined_date`, пересобрать админку. (Менять API на camelCase нельзя — публичный сайт `index.html` читает snake_case `logo_url` и т.п.)

### 🟠 BUG-2: Битые описания у 4 старых участников
В БД `members.description` у BitHub / Envoys / Royal Inc. / KLN — символы U+FFFD (`�����`), кодировка потеряна при импорте. WeChange — норм; у 6 новых описание пустое. Лечится переимпортом описаний этих 4 (источник aurva.kg).

### 🟠 BUG-3: «Invalid Date» на Заявках и Новостях
Карточки показывают «Invalid Date» (на Курсах даты корректные). Либо несовпадение имени поля даты, либо null. Косметика, но заметна.

### 🟠 BUG-4: Неактивные записи исчезают из админки
`teamMemberController` при отсутствии query-параметра `isActive` по умолчанию фильтрует `is_active=true` (строки 30-34), а админ-страница не передаёт `isActive`. Деактивировав члена команды, его больше **нельзя найти/отредактировать/удалить** в панели. Вероятно так же на members/news/partners. Фикс: в админ-запросах слать `?isActive=` пусто/all, либо в контроллере не фильтровать активность для админ-роли.

### 🟡 BUG-5: Тестовые аккаунты в проде
`testuser@gmail.com`, `testuser@aurva.kg` (+ `admin@aurva.kg`) — убрать перед деплоем (уже в PRE-DEPLOY.md).

### 🟡 BUG-6: Настройки — значения как плейсхолдеры (не подтверждено)
Поля Офис/Телефон/Email на /admin/settings выглядят серыми плейсхолдерами — возможно, сохранённые настройки не подгружаются. Требует проверки.
