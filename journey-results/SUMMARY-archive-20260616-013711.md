## Defects by severity

### 🔴 Critical
1. **`/courses` renders a completely blank `<main>`** — `J010` — The page loads `vue.global.js` (full build with runtime template compiler), which calls `eval()`/`new Function()`. The page's CSP `script-src` has no `'unsafe-eval'`, so Vue throws `Uncaught EvalError` and nothing mounts. The user sees only header + footer, no content, no message. Fix at the source: switch to the runtime-only `vue.esm-browser.js` with pre-compiled render functions (preferred), or add `'unsafe-eval'` to that page's CSP. Other pages (`/about`, `/news`) are unaffected because they don't use the Vue runtime compiler.

### 🟡 Major
1. **News cards don't navigate on a real click** — `J009` — On `/news`, clicking a news card (a visible `<a href="/news-detail.html?slug=...">`) does nothing; the URL stays `/news`. Navigation only fired via a synthetic JS `element.click()`, which means the handler calls `event.preventDefault()` then does a JS navigation the real pointer/keyboard path never reaches. A keyboard or assistive-tech user is likely blocked too. The detail page itself renders correctly once reached. Fix at the handler/anchor layer so a normal click (and Enter on focus) navigates.

### ⚪ Minor / UX
1. **DEV bypass button on the admin login screen** — `J014` — A visible **"DEV: Быстрый вход"** button bypasses credential entry. Must be gated behind `import.meta.env.DEV` so it never ships in a production build — otherwise anyone reaching the admin URL gets in without credentials. (Functionally PASS for the gating test, but security-relevant — verify it's excluded from prod.)
2. **Raw-JSON 404** — `J013` — Unknown URLs return `{"success":false,"error":"Cannot GET /..."}` as raw JSON on a blank page. Technically handled (PASS, negative path), but no branding/nav/"home" link. Add a branded Russian HTML 404 handler.
3. **Homepage footer shows placeholder contacts** — (exploration / architect) — Homepage footer rendered `info@aurva.kg` and `+996 XXX XXX XXX` placeholders, while the mid-page contact section and the `/about` footer show the real `aurva.kg@gmail.com` / `+996 550 99 90 10`. Likely a data-loading bug on the homepage footer.
4. **Footer legal links are dead** — `J012` — «Политика конфиденциальности» and «Устав» both point to `href="#"`. Wire to real pages/PDFs before public launch.
5. **Duplicate `<h1>` + icon-only share links on news detail** — `J009` — Two `h1`s (hero + article body) hurt SEO/semantics; the «Поделиться» links are icon-only with no `aria-label` (inaccessible).
6. **Swiper loop warning on carousels** — `J001`, `J004` — Member/other carousels request `loop: true` with only 5 slides; Swiper logs "not enough slides for loop mode" and disables it. Set `loop: false` or duplicate slides.
7. **Navbar inconsistency on `/about`** — `J002` — `/about` replaces the «Кабинет» nav item with «Стать членом» (→ `/#contact`); the homepage keeps «Кабинет». Decide on a consistent header.
8. **Tailwind CDN in production** — all pages — `cdn.tailwindcss.com should not be used in production`; move to a local PostCSS/CLI build.

## UX-discoverability notes
> Highest-value blind-testing signal: where a real user gets lost even though the feature exists.
- **Courses are invisible** — `/courses` is linked in the nav but shows a blank page. A real user clicking «Курсы» sees nothing and no explanation — they'd assume the site is broken (`J010`).
- **News list looks clickable but isn't** — cards have a «Читать» affordance and pointer styling, yet a normal click does nothing. A user would click, see no response, and likely give up on reading any article (`J009`).
- **404 dead-end** — landing on a bad URL drops the user onto raw JSON with no way back into the site (`J013`).
